💡 Persistence Modes

RDB

Point-in-time snapshots at configurable intervals. Compact binary format, fast restart. May lose recent writes on crash.

AOF

Append-only log of every write. Highly durable, configurable fsync. Larger files and slower restart vs RDB.

⚡ 5 Reasons Redis is Fast

🧠 In-Memory Storage

All data lives in RAM. No disk I/O for reads/writes. RAM access is ~100,000× faster than SSD.

🧵 Single-Threaded Command Execution

Zero context switching, zero lock contention, no race conditions. Commands execute atomically in strict order.

📡 I/O Multiplexing (epoll/kqueue)

One thread handles thousands of connections with OS-level non-blocking I/O via an event loop.

🔧 Optimized Data Structures

Custom C implementations with memory-efficient encodings: ziplist, listpack, intset for small objects.

🔗 Lightweight RESP Protocol

Simple Redis Serialization Protocol minimizes parsing overhead on both client and server.

🧵 Single-Thread — The Myth Busted

Redis is single-threaded for command execution. Since Redis 6.0, I/O operations (reading/writing network data) are multi-threaded for higher throughput.

v1–5.xFully single-threaded
v6.0+Multi-threaded I/O, single-threaded exec
v7.0+Enhanced background threading

📊 Thread Roles (Redis 6+)

Network ReadMulti-thread
Command ParsingMulti-thread
Command ExecutionSingle-thread
Network WriteMulti-thread

⚠️ Single-Thread Gotchas

Avoid O(N) blocking commands like KEYS *, LRANGE 0 -1 on huge datasets — they block all other clients. Use SCAN for iteration and pipeline commands for batching to maintain throughput.

CHAPTER 03

Jedis vs Lettuce

Choosing the right Java Redis client for your application

🎣

Jedis

Classic
✅ Simple and easy to use
✅ Synchronous (blocking)
✅ Mature, widely documented
⚠️ Not thread-safe (use JedisPool)
❌ No async/reactive support
❌ Connection-per-thread model
🥬

Lettuce

Modern Default
✅ Thread-safe — shared connections
✅ Async & Reactive (Project Reactor)
✅ Default client in Spring Boot
✅ Netty-based NIO
✅ Cluster & Sentinel support
✅ Optional connection pooling

🎣 Jedis Example

// Thread-safe via JedisPool JedisPool pool = new JedisPool("localhost", 6379); try (Jedis jedis = pool.getResource()) { jedis.set("key", "value"); String val = jedis.get("key"); }

🥬 Lettuce Example

// Shared thread-safe connection RedisClient client = RedisClient .create("redis://localhost"); StatefulRedisConnection<String,String> conn = client.connect(); RedisCommands<String,String> cmd = conn.sync(); cmd.set("key", "value"); String val = cmd.get("key");
CHAPTER 04

How Redis Session Works

Distributed, stateless session management with Redis as the central store

🔄 Traditional vs Redis-Based Sessions

❌ Sticky (In-Memory) Sessions
Browser → Server A → stores session in memory
Browser → Server B → Session not found! ❌

Problems: No horizontal scaling, no failover, sticky load balancing required.
✅ Redis-Based Sessions
Browser → Server A → Redis (stores session)
Browser → Server B → Redis → Session found! ✅

Stateless servers, shared session store, full horizontal scaling.

🗂️ Redis Session Data Structure

# Spring Session Redis key pattern spring:session:sessions:<sessionId> spring:session:sessions:expires:<id> # Hash fields inside each session HGETALL spring:session:sessions:abc123 lastAccessedTime → 1700000000000 maxInactiveInterval → 1800 creationTime → 1699998200000 sessionAttr:user → "serialized_data"

⏰ TTL & Expiration

  • Redis TTL auto-expires stale sessions
  • Each request resets TTL (sliding window)
  • Default: 30 min inactivity timeout
  • Explicit DEL on logout/invalidation
💡 Session fixation protection: Spring Session regenerates the session ID automatically after successful authentication.
CHAPTER 05

Spring Boot Integration

Complete step-by-step Redis session setup

1️⃣ pom.xml Dependencies

<!-- Redis + Session starters --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-data-redis</artifactId> </dependency> <dependency> <groupId>org.springframework.session</groupId> <artifactId>spring-session-data-redis</artifactId> </dependency>

2️⃣ application.yml

spring: data: redis: host: localhost port: 6379 password: secret lettuce: pool: max-active: 10 max-idle: 5 session: store-type: redis redis: namespace: myapp:session flush-mode: on-save timeout: 30m

3️⃣ Config Class

@Configuration @EnableRedisHttpSession( maxInactiveIntervalInSeconds = 1800 ) public class RedisSessionConfig { @Bean public LettuceConnectionFactory connectionFactory() { return new LettuceConnectionFactory( new RedisStandaloneConfiguration( "localhost", 6379) ); } }

4️⃣ Controller

@RestController public class AuthController { @PostMapping("/login") public ResponseEntity login( HttpSession s, @RequestBody LoginReq r) { s.setAttribute("user", r.getUsername()); s.setAttribute("role", "ADMIN"); return ResponseEntity.ok("Logged in"); } @GetMapping("/me") public String me(HttpSession s) { return (String) s.getAttribute("user"); } @PostMapping("/logout") public ResponseEntity logout(HttpSession s) { s.invalidate(); // DEL key in Redis return ResponseEntity.ok("Bye!"); } }
